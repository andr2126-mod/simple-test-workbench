# Таблица переходов жизненного цикла Run

Диаграмма: lifecycle.puml. Состояния совпадают с перечислением RunStatus в доменной модели: PENDING, RUNNING (составное: EXECUTING, ANALYZING), PASSED, FAILED, ERROR, CANCELLED. Строки, отмеченные ★, — переходы, найденные при переборе пар «состояние × событие» (описание в конце файла).

| Из состояния | Событие | Условие | Действие | В состояние |
| --- | --- | --- | --- | --- |
| начало | создать() | токен действителен, набор привязан к ветке | сохранитьИдемпотентныйКлюч() | PENDING |
| начало | создать() | токен недействителен или набор не привязан | отклонить запрос | Run не создаётся |
| PENDING | средаДоступна | - | занятьСреду() | RUNNING |
| PENDING | средаНедоступна | - | записатьПричину() | ERROR |
| PENDING | отменить() ★ | - | - | CANCELLED |
| PENDING | повторный запрос с тем же ключом | - | вернуть существующий runId | PENDING |
| PENDING | повторить() | - | отказать: Run не завершён | PENDING |
| RUNNING (EXECUTING) | всеТестыВыполнены | - | сохранитьРезультаты() | RUNNING (ANALYZING) |
| RUNNING (ANALYZING) | анализЗавершён | нет упавших тестов, кроме флаки | выявитьФлаки(), построитьОтчёт() | PASSED |
| RUNNING (ANALYZING) | анализЗавершён | есть упавшие тесты, не флаки | выявитьФлаки(), построитьОтчёт() | FAILED |
| RUNNING | узелУпал ★ | attempt < maxAttempts | attempt++, освободитьСреду() | PENDING |
| RUNNING | узелУпал ★ | attempt >= maxAttempts | записатьПричину(), освободитьСреду() | ERROR |
| RUNNING | after(maxRunTime) ★ | - | остановитьПрогон(), записатьПричину(), освободитьСреду() | ERROR |
| RUNNING | отменить() ★ | - | остановитьПрогон(), освободитьСреду() | CANCELLED |
| RUNNING | повторить() | - | отказать: Run не завершён | RUNNING |
| PASSED | отменить() ★ | - | отказать: Run уже завершён | PASSED |
| PASSED | повторить() | - | отказать: перезапускать нечего | PASSED |
| FAILED | повторить() | - | создать новый Run (повтор исходного) | FAILED (новый Run в PENDING) |
| FAILED | отменить() ★ | - | отказать: Run уже завершён | FAILED |
| ERROR | повторить() | - | создать новый Run (повтор исходного) | ERROR (новый Run в PENDING) |
| ERROR | отменить() ★ | - | отказать: Run уже завершён | ERROR |
| CANCELLED | повторить() | - | создать новый Run (повтор исходного) | CANCELLED (новый Run в PENDING) |
| CANCELLED | отменить() ★ | - | ничего не делать (идемпотентно) | CANCELLED |

PASSED, FAILED, ERROR и CANCELLED - конечные состояния: Run в них не изменяется, перезапуск создаёт новый Run со ссылкой на исходный (связь «повтор исходного» в доменной модели).

## Найденные дыры и что с ними сделано

**Н-1. Не было состояния «тесты выполняются».** В модели один статус PENDING одновременно означал «Run создан и ждёт» и «тесты идут». Из-за этого нельзя было различить, что отмена или сбой происходят уже во время выполнения, и не к чему было привязать освобождение среды. Решение: добавлено составное состояние RUNNING (вложенные EXECUTING и ANALYZING) с действиями entry занятьСреду() и exit освободитьСреду(). Обновлены: перечисление RunStatus в доменной модели, узлы объектов в object-flow.puml, шаги 5 и 9 сценария ВИ-06, условия опроса в диаграммах последовательности и коммуникации.

**Н-2. Событие «отменить» не описано в сценариях.** Статус CANCELLED был в доменной модели, но ни один сценарий не приводил к нему, а для завершённых Run было неясно, что делать с отменой. Решение: в ВИ-06 добавлено исключение И-5 (CI-сервер отменил сборку); в завершённых состояниях отмена отклоняется с сообщением «Run уже завершён», в CANCELLED она идемпотентна.

**Н-3. Не описаны сбой узла посреди выполнения и зависший прогон.** Сценарий ВИ-06 (И-3) сразу переводил Run в ERROR при любом сбое среды, а ситуации «прогон не завершается вообще» не было. Решение: сбой узла возвращает Run в PENDING (переход «назад») при условии attempt < maxAttempts, по исчерпании попыток Run переходит в ERROR; зависший прогон по таймеру after(maxRunTime) переходит в ERROR. В доменную модель добавлено поле Run.attempt; сценарий ВИ-06 обновлён (И-3 переписано, добавлено И-6 «превышено время выполнения»).

**Н-4. Допустимость перезапуска не определена.** ВИ-07 в сценариях ПР1 не описан, поэтому неясно, из каких состояний можно перезапускать. Решение: перезапуск допускается только из завершённых состояний FAILED, ERROR и CANCELLED и создаёт новый Run; из PENDING, RUNNING и PASSED он отклоняется. Правок модели это не потребовало, но ВИ-07 стоит описать сценарием.

Значения maxAttempts и maxRunTime задаются конфигурацией и в модели не фиксируются; их нужно согласовать с нефункциональными требованиями (в traceability.md цель для ВИ-01 - 15 минут на 10⁴ тестов).
