# Сравнение диаграммы последовательности и диаграммы коммуникации

На диаграмме последовательности виден порядок сообщений во времени, границы выполнения (activate/deactivate), возвращаемые значения и фрагменты alt, opt и loop: по ней можно проследить, что CI получает идентификатор Run сразу, а тесты выполняются асинхронно. На диаграмме коммуникации этого не видно: нет временной оси и возвратов, а ветвления и циклы сведены к пометкам вроде `*[для каждого теста]`. Зато она показывает структуру связей: какие объекты общаются между собой и сколько собеседников у каждого — например, что `run : Run` связан сразу с `db`, `policy`, `rep` и `integ`, то есть является узловым объектом сценария. Разработчику я бы отдал диаграмму последовательности, потому что она однозначно задаёт порядок вызовов, условия и возвраты — всё, что нужно для реализации; архитектору — диаграмму коммуникации, потому что по ней видны связи между объектами и перегруженные узлы. Ни ту ни другую я бы не рисовал для сценария из одного-двух вызовов без ветвлений, где хватает текстового описания, и для сценария, который ещё не устоялся и устареет раньше, чем будет написан код.
